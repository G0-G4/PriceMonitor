# Сверка полей WB: два артикула

Снимок БД: **2026-09-28**, аккаунт `test`.  
Живые ответы API сняты в тот же день для сверки.  
Сырой дамп: [wb-price-fields-check-2026-09-28.json](wb-price-fields-check-2026-09-28.json).

Предыдущего сбора нет, поэтому колонки «вчера» в UI пустые.

## Как сейчас мапятся поля

| Колонка в UI / Excel | Откуда берём | Поле API / БД |
|---|---|---|
| Vendor | кабинет продавца | `vendorCode` |
| Size | кабинет продавца | `sizes[].techSizeName` |
| seller | кабинет продавца | `sizes[].discountedPrice` → `WbPrice.discounted_price` |
| club | кабинет продавца | `sizes[].clubDiscountedPrice` → `WbPrice.club_discounted_price` |
| SPP | витрина `card.wb.ru` | `sizes[].price.product / 100` → `WbPrice.site_price` |
| Change | расчёт | `сегодняшний SPP / вчерашний SPP` |

Поля, которые **собираем, но в таблице не показываем**:

| Поле БД | Откуда | Что это |
|---|---|---|
| `price` | кабинет `sizes[].price` | цена до скидки продавца |
| `discount` | кабинет `discount` | скидка продавца, % |
| `club_discount` | кабинет `clubDiscount` | скидка клуба, % |
| `wb_discount` | расчёт | `round((1 - site_price / discounted_price) * 100)` — СПП в % |

Если на витрине нет цены (нет остатка), `site_price` и `wb_discount` пустые, в колонке SPP будет «—».

Источники:

- кабинет: `GET discounts-prices-api.wildberries.ru/api/v2/list/goods/filter`
- витрина: `GET card.wb.ru/cards/v4/detail?dest=1259571083` (Москва), цена в копейках

## 1. Бм_мб_собака_лайм_кн · размер 80

- Карточка WB: https://www.wildberries.ru/catalog/1420502757/detail.aspx
- nmID `1420502757`, sizeID `2114075937`, название «Куртка бомбер детский»

### Что лежит в БД

| Поле | Значение |
|---|---|
| price (до скидки продавца) | 6019.00 |
| discounted_price | 4454.06 |
| club_discounted_price | 4231.36 |
| discount | 26% |
| club_discount | 5% |
| site_price | 2587.00 |
| wb_discount | 42% |

### Что увидит пользователь в таблице

| Колонка | Значение | Вердикт заказчика |
|---|---|---|
| seller | **4454.06** | верно, `discountedPrice` кабинета |
| SPP | **2587.00** | верно, `price.product` витрины / 100 |
| club | **4231.36** | не нужна (клуб −5%, это мы и так знаем) |
| WB кошелёк | **нет в данных** | заказчик видит **2309** |

Проверка СПП: `round((1 - 2587 / 4454.06) * 100) = 42`.  
На витрине `basic = 6019`, `product = 2587` — размер в наличии.

Цена кошелька в API не приходит (`price.wallet = 0`), страница считает её сама от СПП.

| Кто смотрит | Процент | Цена на этой карточке |
|---|---|---|
| Инкогнито | «Незалогиненный кошелёк» **2%** | **2535** = floor(2587 × 0.98) |
| Учётка (клуб / +1%) | «ВБ Клуб Аноним кошелёк» **3%** | **2509** = floor(2587 × 0.97) |
| Заказчик | ~10.7% / макс. кошелёк | **2309** |

Процент кошелька задаётся уровнем кошелька пользователя, не карточкой. На другом товаре рубли другие, потому что считаются от его СПП; сам % тот же, пока цена не выше лимита показа (`wlt1DiscountDisplayMaxPrice` = 15 000 ₽ для анонимного).

Тот же nmID, размер 86: те же цены (в кабинете цена не различается по размерам, `editableSizePrice: false`).

## Вопросы к заказчику

1. seller и SPP подтверждены.
2. Третья колонка — **WB кошелёк**, не клуб.
3. Какой кошелёк брать в монитор: публичный инкогнито **2535** (2%), цену с клубом **2509** (3%) или цену заказчика **2309** (~11%)?
4. Если товара нет в наличии, SPP и кошелёк оставляем пустыми?

После ответа по кошельку заменим колонку club.
