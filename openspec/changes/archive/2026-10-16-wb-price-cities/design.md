## Context

Как устроен сбор с витрины сейчас, по `src/api/wb_api.py` в рабочей копии:
- цена размера запрашивается одним городом `SITE_DEST = "-1257786"` (параметры `hide_vflags`/`mtype`);
- остаток считает `_scan_warehouse_stock` по 33 точкам `STOCK_DESTS` (`hide_dtype=13`), волнами по `STOCK_CONCURRENCY = 6`;
- оба запроса идут из Chrome после антибота: сначала пробуется HTTP `card.wb.ru`, он почти всегда отдаёт 403.

`WbService.collect_prices` пишет `WbPrice.site_price`, `site_stock`, `site_stock_capped`. «Изменение Цены %» не хранится: Excel считает его формулой `today/yesterday`, страница — в шаблоне `wb_price.html`. Задача сбора (`Task`) имеет только строку `status`, а когда антибот не пропускает, сбор всё равно заканчивается `FINISHED` с пустой СПП.

Факты из прогонов 16.10.2026, на них опирается дизайн:
- цена в ответе обхода (`hide_dtype=13`) совпала с ценой из запроса цены у всех 1165 размеров;
- в Москве, Саратове и СПб СПП одинакова во всех проверенных зонах доставки одного города (22, 26 и 12 зон);
- две московские точки, `-364001` (центр, точка Evirma для остатков) и `-1257786`, отдают одинаковые наборы складов у всех 1165 размеров;
- в публичном справочнике ПВЗ WB (`static-basket-01.wbbasket.ru/vol0/data/all-poo-fr-v10.json`, около 31 МБ) у каждого ПВЗ есть `dest`.

## Goals / Non-Goals

**Goals:**
- Один проход по городам аккаунта даёт и цену, и остаток, поэтому запросов не больше, чем сейчас.
- Пропуски (размер без цены в части городов, город без ответа, антибот) видны в задаче.
- Смена набора городов не даёт ложного «Изменения цены %».

**Non-Goals:**
- Колонки цены по каждому городу.
- Показ городов расчёта в Excel или на странице.
- Автообновление справочника ПВЗ из приложения.
- Взвешивание городов, например по продажам или населению.

## Decisions

### Цена берётся из ответов обхода, отдельного запроса цены нет
`_scan_warehouse_stock` уже получает `sizes[].price.product` в каждом городе. Он начнёт собирать и цену: `(nm, optionId, dest) → цена или None`. Цикл цены по `SITE_DEST` и сама константа удаляются, `STOCK_DESTS` переезжает в модуль справочника как пресет.

Альтернатива — запрос цены (`hide_vflags`/`mtype`) по каждому городу плюс обход для остатка. Это удваивает число запросов к витрине и повышает риск 429 и антибота. Совпадение цен у 1165 из 1165 размеров даёт основание оставить один запрос.

### Результат витрины — структура с причинами пропусков
`get_site_prices(nm_ids, dests)` вместо `dict` возвращает объект:
- `offers` — по размеру: средняя цена или `None`, остаток, признак `>N`, отпечаток фактически ответивших городов;
- `missing_price` — `{dest: число размеров}`: размер с ценой в одних городах и без цены в другом ответившем городе;
- `failed_dests` — города, по которым все попытки хотя бы одной пачки артикулов закончились неудачей;
- `storefront_blocked` — антибот не пройден.

Сервис превращает это в текст предупреждения. API не знает названий городов, их подставляет сервис из справочника.

### Средняя только по ответившим городам, пустая при неполной цене
Для размера берутся города, которые ответили по пачке его артикула:
- если цена есть во всех этих городах — среднее, округлённое до 0,01;
- если цены нет нигде — `None`;
- если цена есть в части городов — `None`, и счётчик `missing_price` по городам без цены растёт.

Город без ответа в средней не участвует, поэтому отпечаток строки строится по тем городам, которые ответили по этой пачке. Остаток по-прежнему считает `aggregate_size_stock` по наблюдениям ответивших городов.

### Отпечаток набора городов — колонка `WbPrice.site_dests_key`
Значение — первые 12 hex-символов `sha1` от отсортированных `dest`, записанных через запятую. При чтении изменения пустой ключ заменяется ключом набора `[-1257786]`.

`get_wb_price_change` добавляет в `WbPriceChange` поле `dests_changed`. Изменение пустое, если вчерашняя строка есть и ключи различаются. В шаблоне `wb_price.html` блок изменения выводится только при `not dests_changed`. В Excel для таких строк формула не пишется, ячейка остаётся пустой.

Альтернатива — хранить сам список `dest`. Это до 100 чисел в каждой строке каждого дня, а для сравнения хватает хэша.

### Города аккаунта — в `Parameter`
Ключ `wb_dests:<account>`, значение — JSON-список `dest` в порядке выбора. Сделано по образцу `wb_token:<account>`. `delete_wb_account` удаляет и этот ключ. Если записи нет, используется пресет «Как Evirma (33)». При чтении проверяется, что набор не пуст и в нём не больше 100 городов. Коды, которых нет в справочнике, не отбрасываются: город могли удалить при пересборке справочника, а WB продолжает принимать старые коды.

### Справочник — `data/wb_cities.json` и модуль `src/wb_cities.py`
Запись справочника: `{"city", "region", "district", "population", "dest"}`, список отсортирован по округу, региону и убыванию населения.

Модуль `src/wb_cities.py`:
- загружает файл один раз;
- даёт поиск по `dest`;
- хранит пресеты `EVIRMA_33` (нынешний `STOCK_DESTS`, где `-364001` заменён на `-1257786`), `REGIONS_7` и `MOSCOW`.

Путь к файлу задаётся так же, как сейчас к `templates/`, а `data/` добавляется в `include_files` cx_Freeze.

Скрипт `scripts/build_wb_cities.py`:
1. Скачивает список ПВЗ WB (`all-poo-fr-vN.json`, последняя версия, которая отдаётся целиком) и `hflabs/city` (`city.csv`, CC BY 4.0).
2. Привязывает ПВЗ к городу по названию в адресе и расстоянию до центра (до 60 км).
3. Для города берёт `dest` ПВЗ, ближайшего к центру.
4. Для городов из списков Evirma, Минска и Астаны подставляет зашитые коды Evirma.

`-364001` заменяется на `-1257786`: это один город, у них одинаковые СПП и склады, а Москва в справочнике должна быть одна.

### Интерфейс — чистый HTML, htmx и небольшой встроенный JS
В строке аккаунта в `wb_accounts.html` появляется кнопка «Города (N)». Она через htmx раскрывает панель `partials/wb_cities.html`. Панель рендерит весь справочник (около 1100 строк) в `<details>` по округам и регионам с чекбоксами `dest`.

Встроенный JS:
- фильтрует строки по подстроке и снимает свёртку с групп, где есть совпадения;
- рисует чипы выбранных городов;
- выполняет быстрый выбор по спискам `dest` пресетов, которые сервер кладёт в `data-*`.

«Сохранить» отправляет `POST /wb_accounts/{account}/cities` с выбранными `dest`. Сервер проверяет лимит от 1 до 100 и возвращает панель с ошибкой либо с сообщением о сохранении; счётчик на кнопке «Cities (N)» обновляется через `hx-swap-oob`.

Альтернатива — подключить готовый мультиселект, например Tom Select. Это новая зависимость с CDN, а приложение собирается в standalone и должно работать без сети.

### Предупреждение задачи — колонка `Task.warning`
`WbService.collect_prices` возвращает список текстов предупреждений. `ScedulerService._collect_wb` записывает их через `; ` в `task.warning`, статус остаётся `FINISHED`. Шаблон `task.html` для `FINISHED` с `warning` показывает «Finished», «Warning» (`badge-warn`) и текст.

Альтернатива — `status = "WARNING: …"`. Она ломает проверку `FINISHED` и показ задачи как завершённой.

### Миграция `009_wb_cities.sql`
`ALTER TABLE Task ADD COLUMN warning TEXT` и `ALTER TABLE WbPrice ADD COLUMN site_dests_key TEXT`. В комментариях нельзя ставить `;`: загрузчик миграций режет файл по этому символу.

## Risks / Trade-offs

- [Цена из `hide_dtype=13` разойдётся с ценой запроса с `hide_vflags`/`mtype`, если WB поменяет витрину] → совпадение проверено на 1165 размерах. Если расхождение появится, вернуть отдельный запрос цены по городам: структура результата этого не меняет.
- [В первый день после обновления у всех строк пустое «Изменение цены %»: набор по умолчанию сменился с Москвы на 33 города] → ожидаемо и согласовано, со второго дня изменение считается.
- [Средняя по 33 городам примерно на 1 п.п. СПП выше московской и перестаёт совпадать с колонкой «Москва» Evirma до рубля] → продавец может выбрать «Только Москва».
- [100 городов — это 100 × пачки запросов. Сбор дольше, растёт риск 429 и антибота] → лимит 100, повтор при 429 уже есть, города без ответа попадают в предупреждение.
- [Справочник устаревает: появляются новые города, а коды ПВЗ меняются] → сохранённые коды продолжают работать, справочник пересобирается скриптом вручную.
- [Сопоставление ПВЗ с городами упрощённое: около 28 тыс. пригородных ПВЗ ни к одному городу не привязано] → для выбора города это не мешает, поле `population` позволяет показать крупные города первыми.
- [Один город, не ответивший по одной пачке, меняет отпечаток только у её артикулов, и на следующий день у них пустое изменение] → это честно: цена действительно посчитана по другому набору. В задаче есть предупреждение.

## Migration Plan

1. Отдельным коммитом зафиксировать текущую работу: обход 33 городов, миграцию `008`, фиксированную Москву.
2. Выкатить изменение. Миграция `009` применится на старте, аккаунты без записи `wb_dests:` начнут собираться по «Как Evirma (33)».
3. Откат — вернуть предыдущую сборку. Новые колонки старый код не читает. Записи `wb_dests:` в `Parameter` можно оставить.
