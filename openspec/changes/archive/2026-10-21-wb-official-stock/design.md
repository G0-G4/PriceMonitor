## Context

Сейчас `WbApi.get_site_prices` за один обход витрины по городам аккаунта собирает и цену, и остаток. Остаток собирают `_collect_stock_observations`, `aggregate_size_stock` и `merge_size_stock`: максимум по каждому складу среди городов, затем сумма по складам. Результат лежит в `WbSiteOffer.stock` и `stock_capped`. `WbService.collect_prices` пишет его в `WbPrice.site_stock` и `site_stock_capped`, а Excel и `wb_price.html` показывают его с `>` при обрезке.

Методы API проверены по документации dev.wildberries.ru 20.10.2026 и пробными запросами 21.10.2026 с персональным токеном аккаунта `test` (категории «Контент», «Цены и скидки», «Маркетплейс», «Аналитика»):

| Источник | Метод | Ограничения |
|---|---|---|
| Склады продавца | `GET marketplace-api.wildberries.ru/api/v3/warehouses` | «Маркетплейс», любой тип токена, 300/мин, ответ 4xx считается за 10 запросов |
| Остаток FBS | `POST marketplace-api.wildberries.ru/api/v3/stocks/{warehouseId}`, тело `{"chrtIds": [...]}` до 1000 → `{"stocks":[{"sku","chrtId","amount"}]}` | то же |
| Остаток FBO | `POST seller-analytics-api.wildberries.ru/api/analytics/v1/stocks-report/wb-warehouses`, тело `{"nmIds": [...] до 1000, "limit", "offset"}` → `data.items[]` с `nmId`, `chrtId`, `quantity`, `inWayToClient`, `inWayFromClient` | «Аналитика», только персональный или сервисный токен (или базовый с секретом), 3/мин, данные обновляются раз в 30 мин |

Что показала проверка на артикуле 180081238:
- `chrtId` совпадает с нашим `size_id` (`sizeID` из API цен) у всех 10 размеров;
- у аккаунта 10 складов продавца, один из них `deliveryType 6` («EDBS Экспресс Балаково»). Метод остатков FBS отвечает по каждому складу и на все запрошенные `chrtId`, в том числе с `amount: 0`;
- сумма FBS из Marketplace API совпала с `stocks-report/seller-warehouses` по всем размерам;
- `wb-warehouses` вернул одну строку «Склад WB» на размер.

## Goals / Non-Goals

**Goals:**
- Остаток по всем складам продавца и WB, без зависимости от витрины.
- Сбор выдерживает лимит FBO (3/мин) при тысячах артикулов.
- Неполный остаток не выдаётся за полный.

**Non-Goals:**
- Колонки FBS и FBO по отдельности, разбивка по складам.
- Товар в пути (`inWayToClient`, `inWayFromClient`).
- Остаток по чужим артикулам. В отчёте только товары кабинета из API цен.
- Проверка прав токена до запросов. Права определяются по ответам API.
- Остатки за прошлые дни (`STOCK_HISTORY_DAILY_CSV`).

## Decisions

### FBS — Marketplace API, а не `stocks-report/seller-warehouses`
Оба источника дали одинаковые суммы. Marketplace API отдаёт данные сразу (Аналитика — с задержкой до 30 минут), работает с любым типом токена и допускает 300 запросов в минуту против 3. FBO берётся из Аналитики, потому что другого источника текущего остатка на складах WB нет: `statistics-api …/supplier/stocks` из документации пропал, а `warehouse_remains` асинхронный и с лимитом 1/мин.

### Новый метод `WbApi.get_stocks(token, nm_ids, chrt_ids) -> StockResult`
`StockResult`: `stocks: dict[int, int] | None` (chrtId → штуки, `None` если остаток не получен целиком), `errors: list[StockError]` (источник `fbs`/`fbo`, HTTP-статус, текст). Порядок работы:
1. `GET /api/v3/warehouses`. Берутся все склады, без фильтра по `deliveryType` и `isDeleting`: у удаляемого склада остаток и так 0, а у DBS и экспресса остаток настоящий.
2. Для каждого склада — `POST /api/v3/stocks/{id}` пачками по 1000 `chrtId`, суммируется `amount`. Паузы 200 мс между запросами, на 429 — повтор по `X-Ratelimit-Retry`, как в `_post_json`.
3. `POST stocks-report/wb-warehouses` пачками по 1000 `nmIds`, с `offset`, пока строк меньше `limit`. Суммируется `quantity` по `chrtId`. Между запросами пауза 20 с. Ответ 204 — пустая пачка, не ошибка.
4. Если любой шаг FBS или FBO закончился ошибкой после повторов, `stocks = None`.

`chrt_ids` берутся из `sizes[].sizeID` ответа API цен, `nm_ids` — из `nmID`. Отдельный запрос карточек не нужен.

Альтернатива — при ошибке FBO оставлять FBS. Отвергнута: число выглядело бы правдоподобным, но было бы занижено. Пустое значение с предупреждением честнее (см. spec `wb-official-stock`).

### Витрина больше не считает остаток
Из `wb_api.py` удаляются `_stock_rows`, `_collect_stock_observations`, `SizeStock`, `aggregate_size_stock` и `merge_size_stock`. Из `WbSiteOffer` удаляются `stock` и `stock_capped`. Обход по-прежнему видит размер без цены (`price=None`), поэтому пропуск цены по-прежнему отличается от неудачного запроса. URL обхода (`hide_dtype=13`) не меняется: цена из него сверена на 1165 размерах, смена параметров потребовала бы новой сверки.

Сбор остатка и обход витрины независимы и запускаются через `asyncio.gather`, поэтому паузы FBO (20 с) идут параллельно с обходом городов.

### Запись в БД без миграции
Остаток пишется в `site_stock`, `site_stock_capped = 0`. Если `stocks is None` или размера нет в словаре при неудаче, `site_stock = None`, `site_stock_capped = None`. Размер, которого нет в ответах при успешных обоих источниках, получает 0. Название колонки `site_stock` остаётся неточным, но переименование потребовало бы миграции и правок в DTO, шаблоне и Excel ради имени.

### Тексты предупреждений по статусу ответа
- FBS 401/403 → «WB stock: the token needs the Marketplace category».
- FBO 401/403 → «WB stock on WB warehouses: the token must be Personal (or Service) with the Analytics category».
- Другое (5xx, сеть, 429 после повторов) → «WB stock was not loaded from <источник>: <status>».

Тексты на английском, как остальные предупреждения в `_site_warnings`, и объединяются с ними. Тип токена из JWT не читается: 403 и так говорит, что не так, а разбор JWT добавил бы зависимость от его формата.

### Подсказка в заголовке колонки
В `wb_price.html` title колонки остатка меняется на «Stock on seller (FBS) and WB (FBO) warehouses from the seller API. > on older days means Wildberries clipped the quantity.». Показ `>` для старых строк остаётся.

## Risks / Trade-offs

- [FBO отстаёт до 30 минут, FBS — нет] → в сумме два среза за разное время. Для ежедневного отчёта это приемлемо.
- [Остаток не совпадёт до штуки с Evirma и витриной: там «доступно к заказу», у нас «на складе»] → сверка 21.10 дала совпадение по 7 размерам из 10. Расхождения объясняются в подсказке и в ответе клиенту.
- [У многих клиентов базовый токен без «Маркетплейса» и «Аналитики»] → остаток будет пустым с предупреждением, что исправить. В день выкатки об этом нужно сказать клиентам.
- [Лимит FBO 3/мин на профиль продавца, а не на токен] → если тот же кабинет параллельно опрашивает другой сервис, будут 429. Повтор по `X-Ratelimit-Retry`, затем ошибка и предупреждение.
- [Скачок остатка в день выкатки] → это ожидаемо и описано в proposal. На «Изменение цены %» не влияет.
- [Плавающая сумма из-за складов с `isDeleting`] → у таких складов 0, на сумму они не влияют.

## Migration Plan

1. Выкатить. Миграции БД нет.
2. Попросить клиентов перевыпустить токен: персональный, «Только чтение», категории «Контент», «Цены и скидки», «Маркетплейс», «Аналитика». Вставить его в настройках аккаунта.
3. Откат — вернуть предыдущую версию. Строки, собранные новой версией, остаются с остатком из API и `site_stock_capped = 0`, старая версия их читает.
